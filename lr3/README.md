# ЛР3 Классификация изображений отходов

Кононенко С. В., группа 4332, вариант 6. [Открыть выполненный ноутбук](../ЛР3_вариант6_классификация_отходов_Kaggle.ipynb).

## Обновление автоэнкодера

Обучение разделено на предобучение восстановлению изображения, обучение Dense-головы при замороженном энкодере и совместную точную настройку энкодера и головы по меткам классов. Итоговый классификатор принимает RGB-фотографию и выдаёт шесть вероятностей softmax.

В «Лекции 3», слайд 6, изложена общая схема предварительного обучения и последующей настройки всей сети. На слайдах 64–67 рассмотрены Dense, softmax и классификационная функция потерь. Конкретная свёрточная архитектура в ноутбуке адаптирована к фотографиям отходов. Приёмы EarlyStopping, ModelCheckpoint и ReduceLROnPlateau рассмотрены в «Лекции 2», слайды 43–48.

## Повторный запуск

1. Скачайте весь репозиторий через **Code → Download ZIP** или клонируйте его. Откройте корневую папку, где находится ноутбук.
2. В окружении Python 3.12 установите зависимости командой `python -m pip install -r lr3/requirements.txt`.
3. Откройте ноутбук в Jupyter или VS Code, выберите это окружение и выполните все ячейки сверху вниз.

По умолчанию `EPOCH_MULTIPLIER` равен `3`. Лимиты CNN, MobileNetV2, предобучения автоэнкодера и обучения его головы составляют 30, 21, 18 и 54 эпохи. Совместная настройка энкодера и головы ограничена 30 эпохами. EarlyStopping может остановить обучение раньше. Фактические значения сохраняются в `lr3/results/training_epochs.csv` и в самом ноутбуке.

Можно запустить из терминала Linux или macOS и сохранить новый результат отдельно:

```bash
python -m nbconvert --execute --to notebook \
  --ExecutePreprocessor.timeout=-1 --output "ЛР3_повтор.ipynb" \
  "ЛР3_вариант6_классификация_отходов_Kaggle.ipynb"
```

Переменная окружения `LR3_EPOCH_MULTIPLIER` позволяет изменить множитель перед запуском. Каждый запуск заново обучает модели. Лучшие веса каждого этапа сохраняются локально по validation loss. Итоговый классификатор `ae64_classifier.keras` пригоден для загрузки через `tf.keras.models.load_model`. Он принимает RGB-пиксели 0–255, размер 96 × 96, и нормализует их внутри модели.

## Данные и результаты

[TrashNet](data/trashnet.zip) содержит 2 527 снимков. Сравнение SHA-256 каждого изображения подтвердило совпадение всех фотографий с [Kaggle Garbage Classification](https://www.kaggle.com/datasets/asdasdasasdas/garbage-classification). После удаления шести конфликтующих меток остаётся 2 521 снимок. Разбиение с seed 42 составляет 1 764 train, 378 validation и 379 test.

Архив имеет SHA-256 `0bf472790f8b20e5c950d5b5012a9d38af0d3392efd65f8ce171334fc16b07c2`. [Авторы TrashNet — Gary Thung и Mindy Yang](https://github.com/garythung/trashnet), [лицензия](data/TRASHNET-LICENSE.txt).

[ImageNet-веса MobileNetV2](data/mobilenet_v2_weights_tf_dim_ordering_tf_kernels_1.0_96_no_top.h5) для входа 96 × 96 находятся рядом с данными. [Исходный релиз](https://github.com/JonathanCMitchell/mobilenet_v2_keras/releases/tag/v1.1), [лицензия](data/MOBILENETV2-LICENSE.txt).

В `results` сохраняются метрики, истории обучения, таблицы, test-прогнозы и итоговая модель. Веса промежуточных контрольных точек сохраняются при запуске и исключены из Git через `.gitignore`.
